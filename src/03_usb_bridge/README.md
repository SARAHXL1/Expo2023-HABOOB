# جسر USB

البديل عن الواي فاي، ويُستخدم أيضًا لاختبار الحساسات قبل إعداد الشبكة إطلاقًا.

يقرأ المنفذ التسلسلي بسرعة 115200، ويأخذ **فقط** الأسطر التي تبدأ بـ `DATA:`،
ويرسل ما بعدها إلى الخادم على `/api/readings` مع ترويسة تبيّن أن طريقة الاتصال USB.

## التشغيل

```bash
python3 03_usb_bridge/serial_bridge.py --list        # عرض المنافذ المتاحة
python3 03_usb_bridge/serial_bridge.py               # اختيار تلقائي
python3 03_usb_bridge/serial_bridge.py --port COM3                      # ويندوز
python3 03_usb_bridge/serial_bridge.py --port /dev/cu.usbserial-0001    # ماك
python3 03_usb_bridge/serial_bridge.py --port COM3 --server http://localhost:5000
```

يحتاج `pip install pyserial`.

## قبل التشغيل

1. **أغلق Serial Monitor في Arduino IDE.** المنفذ لا يُفتح من برنامجين في الوقت نفسه،
   وهذا أكثر سبب لفشل الجسر.
2. استخدم **كابل بيانات**، لا كابل شحن فقط.
3. ثبّت تعريف شريحة USB: CP2102 أو CH340 حسب المكتوب على لوحتك.
4. شغّل الخادم أولًا، ثم الجسر.

## معرفة اسم المنفذ

- **ويندوز:** Device Manager ← Ports (COM & LPT) ← مثل `COM3`
- **ماك:** `ls /dev/cu.*` ← مثل `/dev/cu.usbserial-0001` أو `/dev/cu.SLAB_USBtoUART`
- أو ببساطة: `python3 03_usb_bridge/serial_bridge.py --list`

## السلوك

| المعرّف | السلوك |
|---|---|
| BR-01 | يعيد فتح المنفذ تلقائيًا إن انفصل الكابل، دون أن يتوقف |
| BR-02 | يتجاهل أي سطر لا يبدأ بـ `DATA:`، ويطبع الأسطر الأخرى للتشخيص |
| BR-03 | يتجاهل السطر المعطوب ويستمر |
| BR-04 | يقبل اسم المنفذ والسرعة وعنوان الخادم كمعطيات |
| BR-05 | يعرض قائمة المنافذ إن لم يُحدَّد منفذ |

أسطر التشخيص القادمة من العقدة (نتيجة فحص I2C مثلًا) تُطبع بالبادئة `[عقدة]`،
فتراها دون أن تُرسل للخادم. لإخفائها استخدم `--quiet`.
