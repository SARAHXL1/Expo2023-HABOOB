# هبوب — الموقع الموحد

مجلد واحد فيه كل أكواد هبوب: برنامج العقدة، والخادم، ووحدة الذكاء الاصطناعي، ومنصة التشغيل، وموقع اختبار الحساسات. الشرح الكامل في `دليل_دمج_موقع_هبوب.md` بجانب هذا الملف.

## التشغيل

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests              # اختبارات وحدة AI
python3 02_server_backend/app.py --live --port 5050
```

| الصفحة | العنوان |
|---|---|
| منصة التشغيل (فيها زر «الأعمدة الافتراضية / عمود الاختبار») | `http://localhost:5050` |
| موقع اختبار الحساسات | `http://localhost:5050/bench/` |
| من الجوال مباشرة على عمود الاختبار | `http://<عنوان اللابتوب>:5050/?source=test` |

# هبوب — موقع اختبار الحساسات والقطع

**عقدة استشعار الراحة الحرارية · تحدي 2.3 · هاكثون إكسبو 2030 الرياض**

> مبني على **الإصدار 2** من ملف المتطلبات (5 أكتوبر 2026).

موقع يعمل على اللابتوب، يعرض قيمة كل حساس وحالته، ويحسب UTCI، ويعمل مع عقدة ESP32
عبر الواي فاي أو سلك USB، ويعمل كاملًا **بلا إنترنت**.

بُني حسب «متطلبات موقع اختبار الحساسات» الإصدار 2 و«دليل بناء عقدة هبوب».

## ما تغيّر في الإصدار 2

| | الإصدار 1 | الإصدار 2 |
|---|---|---|
| الاسم | منظومة الراحة الحرارية | **هبوب** |
| الكرة الحرارية DS18B20 | تعمل | **مؤجلة** — التقييم داخل القاعة لا في الشمس |
| MRT | من الكرة بمعادلة ISO | **مفترضة = حرارة الهواء**، وتظهر بشارة «مفترضة» |
| البطارية ودائرتها | تعمل على A1 | **مؤجلة** — التغذية من USB مباشرة |
| حساس الضوء | BH1750 على 0x23 | **VEML7700 على 0x10**، حتى 140,000 لوكس |
| الشاشة | ST7789 2.0 بوصة | **ST7789V2 1.69 بوصة · 240×280** |
| ADS1115 | الموتور والبطارية | **الموتور فقط** (A1 غير مستخدم) |
| عقد البيانات | schema 2 | **schema 3**، وفيه `power_source` |

**لإعادة الكرة الحرارية لاحقًا** يكفي إعداد واحد — انظر قسم «الكرة الحرارية» أدناه.

## التشغيل في 6 خطوات

> لا تحتاج عتادًا للخطوات الخمس الأولى. وضع المحاكاة يجعل الموقع يعمل كاملًا بلا أي قطعة.

### 1. تثبيت المتطلبات

```bash
pip install pythermalcomfort pyserial
```

`pythermalcomfort` لحساب UTCI وMRT. `pyserial` لجسر USB فقط.
الخادم واللوحة لا يحتاجان أي مكتبة أخرى: كلاهما مبني على مكتبة Python القياسية.

### 2. تشغيل الخادم

**للتجربة بلا عتاد (وضع المحاكاة):**

```bash
python3 02_server_backend/app.py --simulate
```

**لاختبار الحساسات الموصولة فعلًا (وضع العتاد الحقيقي):**

```bash
python3 02_server_backend/app.py --live
```

ويمكن التبديل بين الوضعين من أعلى اللوحة في أي وقت، بلا إعادة تشغيل.

### 3. فتح اللوحة

افتح في المتصفح: **http://localhost:5000**

> **على ماك:** المنفذ 5000 يحجزه «مستقبل AirPlay». الخادم يكتشف ذلك وينتقل
> تلقائيًا إلى 5001 ويطبع العنوان الصحيح — استخدم العنوان الذي يطبعه هو.

يجب أن تظهر كل البطاقات التسع بحالاتها، وقيمة UTCI، والرسوم الصغيرة.
هذه هي **المرحلة 0** من خطة الاختبار.

### 4. تجربة محاكاة الأعطال

من قسم «أدوات» أسفل اللوحة، اختر أعطالًا (حساس مفقود، قراءة خاطئة، انقطاع)
واضغط «تطبيق الأعطال». يجب أن تتغير البطاقات وتظهر رسائل المساعدة.

### 5. التحقق من معايير القبول

```bash
python3 06_tools/acceptance_test.py
```

يشغّل خادمًا مستقلًا ويفحص كل بنود القسم 12 آليًا (29 بندًا)، بلا أي عتاد.

### 6. توصيل العتاد

**بالواي فاي:** الخادم يطبع عند تشغيله عناوين IP الخاصة باللابتوب. انسخ السطر
الجاهز واكتبه في `SERVER_URL` داخل برنامج ESP32، ثم ارفع البرنامج.
الشبكة يجب أن تكون **2.4 GHz** (هوتسبوت الجوال هو الأضمن).

**بسلك USB:**

```bash
python3 03_usb_bridge/serial_bridge.py --list          # معرفة اسم المنفذ
python3 03_usb_bridge/serial_bridge.py --port COM3     # ويندوز
python3 03_usb_bridge/serial_bridge.py --port /dev/cu.usbserial-0001   # ماك
```

أغلق Serial Monitor في Arduino IDE أولًا: المنفذ لا يُفتح من برنامجين معًا.

## الوضعان

في أعلى اللوحة مفتاح يبدّل بين وضعين، ويُحفظ الاختيار في `config.json`:

### 🔌 وضع العتاد الحقيقي

لاختبار الحساسات الموصولة فعلًا.

- **المحاكاة تتوقف فورًا**، وتُخفى عقد المحاكاة تمامًا — حتى لو طلبتها بالاسم.
  فلا يمكن أن تُقرأ قيمة وهمية على أنها قراءة حساس.
- **قبل وصول أول رسالة:** تظهر البطاقات التسع كلها بحالة **«غير متصل»**،
  ومع كل بطاقة رسالة المساعدة الخاصة بها — فترى القائمة الكاملة لما يُفترض
  أن يكون موصولًا، لا صفحة فارغة.
- **بعد وصول أول رسالة:** الحساس الموصول يعرض قيمه بحالة «يعمل»،
  وغير الموصول يظهر **«غير موجود»** بالأحمر مع سبب محتمل.

مثال واقعي في المرحلة 3 (DHT22 وDS18B20 فقط موصولان):

| القطعة | الحالة | القيمة |
|---|---|---|
| حرارة الهواء والرطوبة | يعمل | 24.8 °م · 41% |
| حرارة الكرة | يعمل | 25.2 °م |
| المحول التناظري الرقمي | غير موجود | — |
| مقياس الرياح | غير موجود | — |
| حرارة سطح الأرض | غير موجود | — |
| شدة الإضاءة | غير موجود | — |
| البطارية | غير موجود | — |

وتشرح بطاقة UTCI سبب عدم الحساب: «لا يُحسب UTCI لنقص: سرعة الرياح».

### 🧪 وضع المحاكاة

بيانات وهمية واقعية بلا أي عتاد — لاختبار اللوحة والتدرب على العرض.

- عقدتان: **عقدة محاكاة 1** و**عقدة محاكاة 2** (معرّفاهما `sim-01` و`sim-02`،
  مستقلان عن `node-01` حتى لا تختلط البيانات في قاعدة البيانات والرسوم).
- قسم «محاكاة الأعطال» في الأدوات يتيح فصل حساس أو إفساد قراءته أو قطع العقدة.
- إن كانت عقدة حقيقية موصولة في الوقت نفسه فستظهر أيضًا، وتُميَّز باسمها.

### التبديل

| الطريقة | الأمر |
|---|---|
| من اللوحة | زرّا **🔌 العتاد الحقيقي** و**🧪 المحاكاة** أعلى الصفحة |
| عند التشغيل | `--live` أو `--simulate` |
| من الملف | `"mode": "live"` أو `"sim"` في `config.json` |

## حالات القطع

| الحالة | المعنى | اللون |
|---|---|---|
| يعمل `ok` | موجودة وقراءتها منطقية | أخضر |
| غير موجود `not_found` | لم تستجب عند التشغيل | أحمر |
| قراءة خاطئة `read_error` | موجودة لكن القراءة فشلت | برتقالي |
| خارج المدى `out_of_range` | القراءة خارج المدى المنطقي | أصفر |
| متوقف `stale` | لم تصل قراءة جديدة منذ 30 ثانية | رمادي |
| معطّل `disabled` | معطلة عمدًا من الإعدادات | رمادي فاتح |
| مفترض `assumed` | بلا طريقة للتحقق، مثل الشاشة | أزرق |

كل شارة فيها **الكلمة واللون معًا**، لمن لا يميز الألوان.

## ملف الإعدادات `config.json`

كل الأرقام والحدود في هذا الملف، ولا تحتاج لتعديل الكود:

- `server.port` — منفذ الخادم (5000)
- `timing.sensor_stale_s` — متى تصبح القطعة «متوقفة» (30 ثانية)
- `timing.node_offline_s` — متى تصبح العقدة «غير متصلة» (15 ثانية)
- `ranges` — المدى المنطقي لكل قيمة (الجدول 3.3)
- `mrt_source` — **المفتاح الوحيد للكرة الحرارية**: `assumed` أو `globe`
- `globe` — قطر الكرة (0.04 م) وانبعاثيتها (0.95)، تُستخدم عند `globe` فقط
- `nodes` — معاملات المعايرة لكل عقدة: K وB وV_MIN وارتفاع الرياح وتصحيح الكرة
- `disabled_sensors` — القطع المعطلة عمدًا، مثل `["bh1750"]` في العرض الداخلي
- `checks` — حدود الفحوص المنطقية CK-01 إلى CK-06

معاملات المعايرة يمكن حفظها أيضًا **من اللوحة مباشرة** دون إعادة برمجة ESP32.

## الكرة الحرارية: مؤجلة، وكيف تعود

الكرة مؤجلة لأن التقييم داخل القاعة، فـ MRT تُفترض مساوية لحرارة الهواء،
وتظهر في اللوحة بشارة **«مفترضة»** بجانبها حتى لا يُظن أنها مقيسة.

لإعادتها — ثلاث خطوات:

1. وصّل DS18B20 على GPIO 13 مع مقاومة 4.7kΩ بين DATA و3V3.
2. في برنامج العقدة: `#define ENABLE_GLOBE 1`
3. في `config.json`: `"mrt_source": "globe"`

الخطوة الثالثة وحدها تكفي من ناحية الخادم: تُفعَّل بطاقة DS18B20، ويُحسب
MRT من الكرة، ويعمل الفحصان CK-01 وCK-05 وتصحيح الكرة، وتدخل `tg_c`
في القيم الأساسية لـ UTCI. ثم نفّذ المعايرة: قارن حساس الكرة مع DHT22
في الظل، وسجّل الفرق كمعامل تصحيح في نموذج المعايرة باللوحة.

## حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| **المنفذ 5000 مشغول (ماك)** | «مستقبل AirPlay» في macOS يحجزه. الخادم ينتقل تلقائيًا إلى 5001 ويخبرك — فقط اكتب المنفذ الجديد في إعدادات ESP32. أو أطفئ المستقبل من: إعدادات النظام ← عام ← AirDrop و Handoff |
| اللوحة تقول «تعذر الاتصال بالخادم» | تأكد أن نافذة الخادم ما زالت تعمل |
| ESP32 لا يصل للخادم | الشبكة 2.4 GHz؟ العنوان صحيح؟ جدار الحماية يسمح لـ Python على المنفذ 5000؟ |
| تغيّر عنوان اللابتوب | أعد تشغيل الخادم، وانسخ العنوان الجديد إلى `SERVER_URL` |
| جسر USB لا يفتح المنفذ | أغلق Serial Monitor، وتأكد من كابل بيانات لا شحن، ومن تعريف CP2102 أو CH340 |
| UTCI لا تظهر | اللوحة تشرح السبب في مكان الرقم: قيمة ناقصة، أو مدخلات خارج حدود المعادلة |
| بطاقة «معطّل» رمادية | قطعة مؤجلة عمدًا (الكرة أو البطارية)، لا عطل |
| شارة «مفترضة» بجانب MRT | طبيعي: الكرة مؤجلة فـ MRT = حرارة الهواء |
| «رياح مقيّدة» | طبيعي داخل الغرف: معادلة UTCI لا تقبل رياحًا أقل من 0.5 م/ث، فيرفعها الخادم ويخبرك |
| لا تظهر البطاقات | شغّل وضع المحاكاة من «أدوات»، أو `--simulate` عند التشغيل |

## ما لم يُختبر بعد

- **برنامج ESP32 لم يُجرَّب على العتاد**، لعدم توفر اللوحة والحساسات أثناء البناء.
  الخادم واللوحة وجسر USB وعقد البيانات مُختبرة كاملة (29 بندًا آليًا، وجسر USB
  جُرّب على منفذ تسلسلي وهمي).
- أرقام المنافذ منقولة من دليل البناء، وتُراجع على الطباعة الموجودة على لوحتك.
- شاشة 240×280 قد تحتاج ضبط إزاحة حسب الوحدة (انظر README مجلد العقدة).
- معاملا الرياح `K = 20` و`B = 0.5` قيمتان مؤقتتان حتى المعايرة بمقياس رياح مرجعي.

اتبع **خطة الاختبار المرحلية** في [05_docs/خطة-الاختبار.md](05_docs/خطة-الاختبار.md):
أضف حساسًا واحدًا في كل مرة، ولا تنتقل لمرحلة قبل نجاح سابقتها.
