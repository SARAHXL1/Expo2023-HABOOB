# عقد البيانات (JSON schema 3)

العقد بين العقدة والخادم. أي تغيير في الهيكل يرفع رقم `schema`.

## الرسالة من العقدة إلى الخادم

```json
{
  "schema": 3,
  "node_id": "node-01",
  "fw": "0.3.0",
  "ts": 1791100800,
  "uptime_s": 742,
  "reset_reason": "POWERON",
  "wifi": {"connected": true, "rssi": -58, "ip": "192.168.1.77"},
  "heap_free": 182340,
  "i2c_found": ["0x10", "0x48", "0x5A"],
  "power_source": "usb",
  "send_interval_s": 5,
  "sensors": {
    "dht22":      {"status": "ok", "ta_c": 24.8, "rh_pct": 41.0},
    "ds18b20":    {"status": "disabled", "tg_c": null, "count": 0},
    "ads1115":    {"status": "ok"},
    "anemometer": {"status": "ok", "wind_v": 0.084, "wind_ms": 1.9,
                   "height_m": 1.8, "samples": 50},
    "battery":    {"status": "disabled", "bat_v": null},
    "mlx90614":   {"status": "ok", "tsurf_c": 27.1, "tamb_c": 26.0},
    "veml7700":   {"status": "ok", "lux": 680},
    "tft":        {"status": "assumed"}
  }
}
```

**الجديد في schema 3:** الحقل `power_source` ("usb")، و`veml7700` بدل `bh1750`،
والكرة والبطارية تُرسلان بحالة `disabled` مع `null` لأنهما مؤجلتان.

## القواعد

| المعرّف | القاعدة |
|---|---|
| DS-01 | الحقل `schema` إلزامي، ويُرفع رقمه عند أي تغيير في الهيكل |
| DS-02 | القيمة غير المتوفرة تُرسل `null`، ولا تُحذف ولا تُرسل كرقم وهمي |
| DS-03 | الوحدات ثابتة في أسماء الحقول: `_c` مئوية، `_pct` نسبة، `_v` فولت، `_ms` متر/ثانية |
| DS-04 | العقدة ترسل القيم الخام، ولا تحسب MRT ولا UTCI |
| DS-05 | رسالة USB هي نفس JSON في سطر واحد، تسبقه البادئة `DATA:` |
| DS-06 | الخادم يقبل حقولًا إضافية غير معروفة ويتجاهلها |

> **DS-06 مهم:** يمكنك إضافة حساس جديد إلى رسالة العقدة دون أن يتعطل الخادم.
> لن تظهر له بطاقة حتى يُضاف إلى `SENSOR_CATALOG` في `02_server_backend/settings.py`.

## الوحدات

| الحقل | الوحدة | المدى المنطقي |
|---|---|---|
| `ta_c` | °م | −10 إلى 60 |
| `rh_pct` | % | 0 إلى 100 |
| `tg_c` | °م | −10 إلى 90 (−127 تعني مجسًا غير متصل) — عند تفعيل الكرة فقط |
| `wind_v` | فولت | 0 إلى 1.0 |
| `wind_ms` | م/ث | 0 إلى 30 |
| `tsurf_c` | °م | −20 إلى 90 |
| `lux` | لوكس | 0 إلى 140,000 (حد VEML7700 في ملف المواصفات) |
| `bat_v` | فولت | 2.9 إلى 4.3 — مؤجلة، التغذية من USB |
| `rssi` | dBm | −90 إلى −30 |

المدى يُضبط من `config.json` في `ranges`.

## الحالات التي ترسلها العقدة

| الحالة | المعنى |
|---|---|
| `ok` | القطعة موجودة والقراءة نجحت |
| `not_found` | لم تستجب عند التشغيل (عنوان I2C غير موجود، أو صفر مجسات) |
| `read_error` | موجودة لكن القراءة فشلت (NaN، أو −127 °م، أو انتهاء المهلة) |
| `assumed` | بلا طريقة للتحقق، مثل الشاشة |

الخادم يضيف ثلاث حالات أخرى: `out_of_range` و`stale` و`disabled`.

## رد الخادم

```json
{
  "accepted": true,
  "utci_c": 23.0,
  "stress_category": "لا يوجد إجهاد حراري",
  "stress_key": "no_stress",
  "mrt_c": 24.8,
  "mrt_source": "assumed",
  "server_time": 1791100805,
  "alerts": 0
}
```

`mrt_source` يساوي `"assumed"` عندما تكون MRT مفترضة مساوية لحرارة الهواء،
و`"globe"` عندما تُحسب من الكرة الحرارية.

العقدة تعرض `utci_c` على الشاشة، وتستخدم `stress_key` لاختيار اللون
(لأن مكتبة الشاشة لا تعرض الحروف العربية).

عند رفض الرسالة يرد الخادم بـ **400**:

```json
{"accepted": false, "error": "الحقل sensors مفقود أو ليس كائنًا."}
```

## رسالة USB

نفس JSON في سطر واحد، بالبادئة `DATA:`:

```
DATA:{"schema":2,"node_id":"node-01",...}
```

العقدة تطبع هذا السطر **دائمًا**، حتى عندما يكون الواي فاي يعمل (FW-07).
أي سطر آخر يُعتبر تشخيصًا ولا يُرسل للخادم.

## الحسابات في الخادم

| المعرّف | الحساب | الطريقة |
|---|---|---|
| CA-01 | سرعة الرياح عند 10 م | `scale_wind_speed_log(v_z1, z2=10, z1=ارتفاع الحساس)` |
| CA-02 | MRT | **مفترضة = حرارة الهواء** ما دامت الكرة مؤجلة؛ وعند `mrt_source = globe` تُحسب بـ `mean_radiant_tmp(tg, tdb, v, d=0.04, emissivity=0.95, standard="ISO")` |
| CA-03 | UTCI وفئة الإجهاد | `utci(tdb, tr=MRT, v=الرياح عند 10م, rh)` |
| CA-04 | حماية المدى | الرياح تُقيَّد إلى 0.5–17 م/ث مع علامة «رياح مقيّدة»؛ وMRT يجب أن تكون بين (tdb−30) و(tdb+70) |
| CA-05 | نسبة البطارية | مؤجلة؛ تعود تلقائيًا إن وصلت قراءة `bat_v` |
| CA-06 | تصحيح الكرة | عند تفعيل الكرة فقط |
| CA-07 | عند غياب قيمة | القيم الأساسية: `ta_c` و`rh_pct` و`wind_ms`، ويُضاف `tg_c` عند تفعيل الكرة |

**MRT تُحسب بسرعة الرياح عند الكرة، لا عند 10 م.** سرعة 10 م تُستخدم لـ UTCI فقط.

## الفحوص المنطقية

| المعرّف | الفحص | التنبيه |
|---|---|---|
| CK-01 | فرق Ta وTg أكبر من 3 °م في الظل وقت المعايرة | تحقق من معايرة الكرة — عند تفعيل الكرة فقط |
| CK-02 | `wind_v` ثابت عند الصفر | تحقق من توصيل الموتور أو اتجاهه |
| CK-03 | `wind_v` سالب | اعكس سلكي الموتور |
| CK-04 | `lux` ثابت عند الصفر في مكان مضاء | تحقق من VEML7700: VIN وSDA وSCL واللحام |
| CK-05 | `tg_c` يتغير أكثر من 10 °م خلال 10 ثوانٍ | قراءة الكرة غير مستقرة — عند تفعيل الكرة فقط |
| CK-06 | إعادة تشغيل متكررة خلال 5 دقائق | غيّر كابل USB أو المنفذ، أو ركّب مكثفًا |

CK-01 يعمل فقط عند تفعيل `checks.calibration_mode` في `config.json`،
لأنه فحص معايرة لا فحص تشغيل. وهو وCK-05 معطلان ما دامت الكرة مؤجلة.

## واجهات API

| الطريقة | المسار | الوظيفة |
|---|---|---|
| POST | `/api/readings` | استقبال رسالة |
| GET | `/api/nodes` | قائمة العقد وحالاتها |
| GET | `/api/latest?node=node-01` | آخر رسالة بعد المعالجة |
| GET | `/api/history?node=node-01&minutes=15` | سلسلة زمنية |
| GET | `/api/export.csv?node=…&from=…&to=…` | تصدير CSV |
| GET | `/api/errors` | الرسائل المرفوضة |
| POST | `/api/calibration` | حفظ معاملات المعايرة |
| POST | `/api/simulation` | تشغيل المحاكاة وضبط الأعطال |
| POST | `/api/config` | تعطيل قطع، ووضع المعايرة |
| GET | `/api/meta` | كتالوج القطع والحدود والفئات |
| GET | `/api/health` | حالة الخادم |
| GET | `/` | لوحة العرض |

### مثال: حفظ المعايرة

```bash
curl -X POST http://localhost:5000/api/calibration \
  -H "Content-Type: application/json" \
  -d '{"node_id":"node-01","wind_k":22.4,"wind_b":0.35,"globe_offset_c":0.8}'
```

تُحفظ في `config.json` وتُطبَّق على الرسائل القادمة فورًا، بلا إعادة برمجة ESP32.
