# الخادم (Backend)

يستقبل رسائل العقدة، ويتحقق منها، ويحدد حالات القطع، ويحسب UTCI، ويخزن،
ويقدم البيانات واللوحة.

## التشغيل

```bash
python3 02_server_backend/app.py              # الوضع العادي، المنفذ 5000
python3 02_server_backend/app.py --simulate   # مع وضع المحاكاة
python3 02_server_backend/app.py --port 5001  # منفذ آخر
```

### إن كان المنفذ مشغولًا

على **ماك**، يحجز «مستقبل AirPlay» المنفذ 5000 (عملية ControlCenter)، وهذا أكثر
سبب لفشل التشغيل من أول مرة. الخادم يكتشف ذلك ويجرّب 5001 إلى 5005 تلقائيًا،
ويطبع تحذيرًا بالمنفذ الذي استُخدم فعلًا، ويظهر المنفذ الصحيح في اللوحة وفي
سطر `SERVER_URL` الجاهز للنسخ.

لإطفاء المستقبل: إعدادات النظام ← عام ← AirDrop و Handoff ← مستقبل AirPlay.
ولتعطيل الانتقال التلقائي: `--no-fallback`.

يستمع على `0.0.0.0` حتى يصل إليه ESP32 من الشبكة المحلية (SV-11)،
ويطبع عند التشغيل عناوين IP الخاصة باللابتوب جاهزة للنسخ (SV-12).

## المكتبات

| المكتبة | الغرض | إلزامية؟ |
|---|---|---|
| `pythermalcomfort` | حساب UTCI وMRT وسرعة الرياح عند 10 م | لحساب UTCI |
| مكتبة Python القياسية | الخادم، والتخزين، وتقديم اللوحة | مدمجة |

الخادم **لا يستخدم أي إطار ويب خارجي** (لا Flask ولا FastAPI): مبني على
`http.server` من المكتبة القياسية، فيعمل على ويندوز وماك بلا تثبيت إضافي.

إن لم تكن `pythermalcomfort` مثبّتة، يبقى الموقع يعمل: تُحسب MRT وسرعة الرياح
بمعادلتيهما القياسيتين، ولا تُحسب UTCI، وتظهر رسالة واضحة في اللوحة
بدل رقم مُختلق.

## الملفات

| الملف | المسؤولية |
|---|---|
| `app.py` | نقطة التشغيل، وتوجيه الطلبات، وواجهات API، وتقديم اللوحة |
| `settings.py` | تحميل `config.json`، وكتالوج القطع (الجدول 3.1)، ورسائل المساعدة (8.4) |
| `processing.py` | التحقق (SV-02)، والحالات، وstale (SV-05)، والفحوص CK-01 إلى CK-06 |
| `calculations.py` | CA-01 إلى CA-07: الرياح عند 10 م، وMRT، وUTCI، والبطارية، وتصحيح الكرة |
| `storage.py` | SQLite، والتاريخ القصير، وتصدير CSV، وسجل المرفوضات |
| `simulator.py` | وضع المحاكاة ومحاكاة الأعطال (SV-13) |

## واجهات API

| الطريقة | المسار | الوظيفة |
|---|---|---|
| POST | `/api/readings` | استقبال رسالة من العقدة أو الجسر |
| GET | `/api/nodes` | قائمة العقد وحالة كل واحدة وآخر ظهور |
| GET | `/api/latest?node=node-01` | آخر رسالة بعد المعالجة: القيم والحالات والمشتقات والتنبيهات |
| GET | `/api/history?node=node-01&minutes=15` | سلسلة زمنية للرسوم |
| GET | `/api/export.csv?node=…&from=…&to=…` | تصدير CSV |
| GET | `/api/errors` | آخر الرسائل المرفوضة وسبب الرفض |
| POST | `/api/calibration` | حفظ معاملات المعايرة لعقدة |
| POST | `/api/simulation` | تشغيل أو إيقاف المحاكاة، وضبط الأعطال |
| POST | `/api/config` | تعطيل قطع، وتشغيل وضع المعايرة |
| GET | `/api/meta` | كتالوج القطع والحدود والفئات (تبني اللوحة نفسها منه) |
| GET | `/api/health` | حالة الخادم وعدد القراءات |
| GET | `/` | لوحة العرض |

`POST /api/readings` يرد بـ: `accepted` و`utci_c` و`stress_category` و`stress_key`
و`mrt_c` و`server_time` — تعرض العقدة منه UTCI على الشاشة (القسم 5.3، FW-11).

## التخزين

قاعدة بيانات SQLite في `data/readings.db`:

- `readings` — الرسالة الخام كما وصلت (`raw_json`، لا تُعدّل أبدًا — NF-08)
  مع القيم المشتقة في أعمدة مستقلة بجانبها.
- `rejected` — الرسائل المرفوضة وسبب الرفض.

تُنظَّف السجلات الأقدم من `server.history_keep_minutes` كل 5 دقائق،
حتى لا يتضخم الملف في تشغيل طويل (NF-04).

## ترتيب المعالجة لكل رسالة

1. **التحقق** من البنية: `node_id` و`sensors` وأن الأرقام أرقام فعلًا (SV-02).
   الرسالة المعطوبة تُرفض برد 400 وسبب عربي، وتُسجَّل.
2. **وقت الاستلام** يُستخدم بدل `ts` إن كان غير منطقي (SV-03).
3. **إعادة حساب سرعة الرياح** من الجهد الخام بمعاملات المعايرة (SV-15).
4. **حالات القطع**: تبدأ مما أرسلته العقدة، ثم يضيف الخادم
   `out_of_range` (SV-04) و`stale` (SV-05) و`disabled`.
5. **الفحوص المنطقية** CK-01 إلى CK-06 وتنبيهات البطارية والإشارة (SV-06).
6. **الحسابات** CA-01 إلى CA-07 (SV-07).
7. **التخزين** مع القيم المشتقة (SV-08).

> **ملاحظة مهمة:** حالتا `stale` و«العقدة غير متصلة» تُعاد حسابهما عند **كل قراءة**
> من `/api/latest`، لا عند الاستلام فقط. لذلك تتحول البطاقة إلى «متوقف»
> من تلقاء نفسها عندما تصمت العقدة، بدل أن تتجمد على آخر قيمة.
